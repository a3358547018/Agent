## 2026-08-08 - Thread-Safe Concurrency with requests.Session
**Learning:** In Python, standard `requests.Session` instances are NOT fully thread-safe when shared across concurrent threads in a `ThreadPoolExecutor`. Sharing a single session can cause state corruption or connection leakages. However, creating a new session for every request completely defeats the connection-pooling performance benefit. Using thread-local storage (`threading.local()`) to maintain a separate `requests.Session` instance per thread guarantees thread safety while still retaining connection reuse within each concurrent worker thread.
**Action:** When implementing parallel network-bound operations with `ThreadPoolExecutor`, always wrap standard `requests.Session` in thread-local storage to balance safety and performance.
