## 2026-05-10 - Thread-Local Requests Session for Safe Concurrent Connection Pooling
**Learning:** Standard `requests.Session` instances are not thread-safe. When parallelizing network-bound operations using `ThreadPoolExecutor` or multiple threads, reusing a single global session can lead to state corruption and socket-level race conditions. However, creating a brand new session per request eliminates the benefits of HTTP connection pooling (keep-alive). Using a thread-local storage (`threading.local`) to manage a `requests.Session` per thread provides a safe, elegant middle ground: threads retain full connection pooling benefits, and requests remain isolated and thread-safe.
**Action:** When parallelizing synchronous `requests` calls in Python, always implement a `_get_session()` utility backed by `threading.local()` within each networking module to ensure concurrent safety and optimal socket reuse.
